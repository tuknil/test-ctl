3. What is policy context?

A policy context is the existing configuration environment where the candidate rule could eventually be used.

akamai-policy:example:rev-17 Example policy-context ID
Selected context IDTarget tool and policy location
↓
Policy snapshot found?Existing-rule summary is available
↓
Yes: continue safelyCheck overlap or conflicts

If no snapshot is found: the result is insufficient-context, and the service stops before an LLM call. This avoids guessing about an existing policy.

4. Live LLM versus fixture mode

Live AT&T LLM mode

  1. Service checks scope and policy context.
  2. AT&T Inference proposes a structured target-rule candidate.
  3. Service validates syntax and checks policy conflicts.
  4. Result shows LLM invoked: yes.

Best for: demonstrating model-assisted rule construction.

Fixture mode

  1. Service checks scope and policy context.
  2. A local deterministic template proposes the candidate.
  3. Service validates syntax and checks policy conflicts.
  4. Result shows LLM invoked: no.

Best for: offline, repeatable demos and automated tests.

6. Durable history dashboard

The translator page lists recent persisted run metadata without loading every full request or candidate. Selecting View retrieves one durable result and keeps the candidate artifact collapsed until requested.

Treat candidate artifacts as sensitive security-control data. The dashboard belongs behind the same authentication and authorization controls as the API.

7. Simple team message

“The LLM helps create the first candidate rule. The service then performs deterministic syntax and policy checks. The result is a reviewable candidate, not an automatic production deployment.”
